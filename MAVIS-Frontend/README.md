# MAVIS Dashboard

Next.js / React / strict TypeScript frontend for architecture learning, source analysis, runtime evidence and versioned coursework. Stage 2 reuses the Stage 1 shell, role navigation and Light/Dark/System semantic styles.

The default is **backend mode**. The shared `/api/mavis` boundary connects the component screens and source analysis to Java. Mock previews require the explicit setting `MAVIS_API_MODE=mock`.

For a new Windows clone, start with [the clean-clone runbook](../docs/CLEAN_CLONE_SETUP.md) and repository-root `Start-Mavis.ps1`. Database credentials and verified-account passwords are intentionally absent from Git. Java and FE must come from the same revision; the integrated FE requires Java `/api/v1/auth/me`.

## Development

Prefer working locally? You need Node.js and npm — [install with nvm](https://github.com/nvm-sh/nvm#installing-and-updating).

```sh
git clone <this-repository-url>
cd <repository-name>/MAVIS-Frontend
npm ci
npm run dev
```

Run `npm run typecheck`, `npm test`, and `npm run build` for verification. Copy `.env.example` to `.env.local` to select mock scenarios or configure backend mode. Never commit session secrets or expose them through `NEXT_PUBLIC_*` settings.

`npm test` includes `tests/edge-semantics.test.cjs`: contract fixture verifying edge direction/labels, graph aggregation, distinct evidence union, and protocol gating against the implementation contract of 24/10/2026. Known open item: UC-01 (message subscribe direction convention) — UC-02 (aggregate resolution status) was closed at the frontend projection by S2c.

Node metadata (protocol, transport authority, resolution issue) is preserved end to end: the graph API exposes it (S2a), the adapter merges it into node properties with a documented precedence (graph value wins; explicit null means unknown; legacy backends fall back to model-detail properties), and the selected-node panel shows it when present (S2b). On a legacy Java backend that omits the graph fields, valid metadata from model-detail properties is still displayed; the block is hidden only when no valid value exists. Message publish/subscribe and database access edges in the C4 Container view show verified protocols from node properties; unverified connections keep their plain action labels without defaulting to JDBC or Kafka. The C1 System Context shows the analyzed system alone without protocols.
