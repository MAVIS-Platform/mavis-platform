# N01 — Internal Worker contract v1

Worker-side implementation is complete. Vũ's V02 review, real Java dispatch/client and end-to-end publication acceptance remain integration work; the fixture consumer below is not that backend client. Worker does not connect to a business database.

## Input and artifact ownership

Java stages an immutable, extracted snapshot at `<ArtifactScope:Root>/<artifactId>` on a volume mounted **read-only** to Worker. `artifactId` is an opaque lowercase 64-hex identifier, not a path or an assertion about the uploaded ZIP hash. Java owns ZIP validation, storage, extraction, permissions, retention and manifest association with project/snapshot. Worker neither downloads URLs nor extracts archives.

`POST /api/v1/dotnet/analyze` and `POST /api/v1/dotnet/jobs` now accept **only**:

```json
{ "schemaVersion": "1.0", "artifactGrant": "<keyId>.<payload-base64url>.<signature-base64url>" }
```

Unknown input fields, including `sourceLocation`, are rejected. This replaces the pre-integration v1 raw-path draft. Internal C# analyzer calls retain a local-path request type for source inspection and tests; it is not the HTTP DTO.

Every `/api/v1` request requires `X-Mavis-Worker-Key`; loopback is no exception. Keep transport on a protected private network/TLS boundary. Grant keys and service keys are separate secrets, supplied through deployment configuration, never committed. The artifact grant is a bearer capability: do not log its body or disclose it to frontend users.

## Grant protocol

1. UTF-8 encode JSON claims (see [claims fixture](contracts/n01/claims.json)). Fields are `schemaVersion=1.0`, `audience=mavis-worker-analysis`, `projectId`, `sourceSnapshotId`, `jobId`, `attemptId`, `artifactId`, `expectedInputDigest`, `deadlineUtc`.
2. Project/snapshot/job/attempt/key IDs contain 1–128 ASCII letters, digits, `_` or `-`. Artifact ID and input digest are exactly 64 lowercase hex characters. Deadline is an ISO-8601 offset timestamp.
3. Base64url encode the payload **without padding**. Sign ASCII bytes of `keyId + "." + payload` with HMAC-SHA256 and the UTF-8 secret from `ArtifactScope:GrantKeys:<keyId>`. Base64url encode the signature without padding. No reserialization/canonical JSON is needed to verify: sign the exact encoded payload bytes.
4. Worker uses a constant-time signature comparison, validates audience/claims, rejects unknown fields, expired deadlines, invalid IDs and excessive lifetime. Default maximum remaining lifetime is 300 seconds; configurable 1–3600 seconds. There is no expiry grace period: synchronize issuer/Worker clocks.
5. Worker maps only the signed artifact ID under its configured root, rejects symlink/junction paths and enforces existing source-file/byte limits. The expected digest must match the supported analysis input fingerprint, **not** Java's uploaded ZIP SHA-256. The exact fingerprint algorithm is in [DOTNET_API_V1.md](DOTNET_API_V1.md).

Rotate grants by temporarily configuring old and new key IDs, issuing only the new ID, then removing the old key after all grants expire. Do not use the fixture key in deployment. Grants authorize execution but cannot make a writable source immutable: Java/operator must enforce the read-only snapshot mount and prohibit concurrent host-side mutation.

## Deadline, attempts and results

Deadline covers queue time as well as execution. At execution, the smaller of remaining absolute deadline and `DotnetAnalysis:TimeoutSeconds` is enforced. Expired queued work never invokes the analyzer. Direct timeout returns 408; background timeout is terminal `TimedOut`. Explicit cancel is `Cancelling`/`Cancelled`, not timeout.

Result echoes `projectId`, `sourceSnapshotId`, `jobId`, `attemptId` and `inputDigest`; evidence paths remain snapshot-relative. Job records are keyed by `(jobId, attemptId)`. Same tuple and identical resolved input is idempotent; changing its snapshot, digest, scope or deadline yields 409. A new attempt ID creates a separate attempt. Get/cancel require `?attemptId=...`; a wrong attempt returns 404 and cannot cancel another attempt. Submit Location includes that query parameter.

Queue/status are bounded and ephemeral; Java remains owner of durable attempts, leases, retry/reconciliation, authorization and model publication. GET/cancel are trusted service operations authenticated by service key; they do not require an unexpired submission grant. Java must enforce its own project policy. Do not treat a Worker `Completed` state as successful canonical model publication.

## Health and errors

- `GET /api/health`: public liveness only.
- `GET /api/health/ready`: public 200 only if service key, usable grant keys, valid scope root and lifetime limits are configured; otherwise 503. No DB or Java connectivity is implied.
- Versioned errors use `application/problem+json` with `type`, `title`, `status`, `code`, `traceId`. No exceptions, filesystem paths, token or secret values are returned. Codes: `INVALID_REQUEST` (400), `SERVICE_AUTH_REQUIRED` (401), `ARTIFACT_SCOPE_DENIED` (403), `NOT_FOUND` (404), `DEADLINE_EXCEEDED` (408), `ATTEMPT_CONFLICT` (409), `CAPACITY_EXHAUSTED` (429), `WORKER_NOT_READY` (503), `WORKER_FAILURE` (500).
- Legacy `/api/analysis` and `/api/jobs` are disabled by default in **every** environment. `WorkerAccess:EnableLegacyAnalysis=true` is an explicit migration-only opt-in to the old contract, not the N01 scoped API. Legacy test fixtures opt in explicitly.

## Build and run

From `MAVIS.Worker`, with the pinned SDK 10.0.204:

```powershell
dotnet restore MAVIS.Worker.slnx --locked-mode
dotnet test tests/MAVIS.Worker.Tests/MAVIS.Worker.Tests.csproj --no-restore
dotnet publish src/MAVIS.Worker.Api/MAVIS.Worker.Api.csproj -c Release --no-restore -p:UseAppHost=false -o .artifacts/worker-publish
docker build -t mavis-worker:n01 .
pwsh -File scripts/Test-N01Image.ps1
```

The Dockerfile packages prepublished output; SDK/package locks govern the publish step. Runtime is digest-pinned ASP.NET 10, non-root UID 1654. `.dockerignore` sends only publish output. Deploy with a read-only source mount, read-only root filesystem, dropped capabilities, `no-new-privileges`, bounded CPU/memory, temporary `/tmp`, and no Docker socket. Configure `WorkerAccess__ApiKey`, `ArtifactScope__Root` and `ArtifactScope__GrantKeys__<keyId>` via your secret/config mechanism. The smoke script uses fixture-only keys and loopback publishing, removes its own container and never starts the Runner.

## Shared fixtures and acceptance

`contracts/n01` contains request/claims, the two source files, the real analyzer result projection and the image-verified N01 error envelope and an offline Java 21/Jackson consumer. The request is deliberately a fixed, expired fixture; replay tests validate its signature using a fixed clock. The image smoke generates a fresh deadline and can regenerate response fixtures with `-UpdateFixtures`. A .NET fixture test detects producer drift. Later static profiles can explicitly export the test-output result with MAVIS_EXPORT_N01_FIXTURE=1, copy/review it into contracts, then rerun with export disabled; this is not a new image smoke proof.

Run Java offline probe from `contracts/n01/java-consumer` with Maven/JDK 21:

```powershell
mvn -B -ntp compile exec:java "-Dexec.args=.."
```

It verifies HMAC, decoded claim JSON, source input digest, provenance fields, evidence and error envelope. It has no platform database/dispatch dependency. Agree this draft grant format and deployment/mount ownership with Vũ before implementing the production Java client. Schema labels matching `1.0` alone do not mean canonical Java findings are already compatible.
