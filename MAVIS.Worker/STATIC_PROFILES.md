# C# static profiles N02–N05

These profiles inspect source only: no target restore, build, MSBuild evaluation or target assembly loading. Java owns final canonical model merge and runtime service/database identity confirmation. `projects` are snapshot-relative .csproj contexts, not discovered runtime service IDs.

## N02 — discovery/config (1.6)

Project/solution declarations are read as metadata. Default compile and configuration ownership use the nearest ancestor project directory; multiple projects in one directory remain separate contexts. Explicit static Compile Include can link already discovered source from another directory. Import/condition/generated target semantics remain unsupported diagnostics.

Generated policy defaults to excluding `.g.cs`, `.g.i.cs`, `.generated.cs` and leading `// <auto-generated` or `/* <auto-generated` banners. Set `DotnetAnalysis:ExcludeGeneratedSources=false` to include them. Generated source still counts toward discovered-file/byte budgets and the input fingerprint. bin/obj/.git/.vs/node_modules are never traversed.

HTTP config key aliases retain effective port, including 80/443 and bracketed IPv6. Config variants are never merged by guessed environment precedence; conflicting values produce an `Ambiguous` reference with evidence from each variant. ConfigurationLiteral means a safe literal was read, not a confirmed Java canonical mapping. Project references distinguish `SnapshotReference`, `Unresolved` and `External`; outside paths are never opened or echoed.
