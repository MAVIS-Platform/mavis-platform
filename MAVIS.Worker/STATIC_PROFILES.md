# C# static profiles N02–N05

These profiles inspect source only: no target restore, build, MSBuild evaluation or target assembly loading. Java owns final canonical model merge and runtime service/database identity confirmation. `projects` are snapshot-relative .csproj contexts, not discovered runtime service IDs.

## N02 — discovery/config (1.6)

Project/solution declarations are read as metadata. Default compile and configuration ownership use the nearest ancestor project directory; multiple projects in one directory remain separate contexts. Explicit static Compile Include can link already discovered source from another directory. Import/condition/generated target semantics remain unsupported diagnostics.

Generated policy defaults to excluding `.g.cs`, `.g.i.cs`, `.generated.cs` and leading `// <auto-generated` or `/* <auto-generated` banners. Set `DotnetAnalysis:ExcludeGeneratedSources=false` to include them. Generated source still counts toward discovered-file/byte budgets and the input fingerprint. bin/obj/.git/.vs/node_modules are never traversed.

HTTP config key aliases retain effective port, including 80/443 and bracketed IPv6. Config variants are never merged by guessed environment precedence; conflicting values produce an `Ambiguous` reference with evidence from each variant. ConfigurationLiteral means a safe literal was read, not a confirmed Java canonical mapping. Project references distinguish `SnapshotReference`, `Unresolved` and `External`; outside paths are never opened or echoed.

## N03 — structure/endpoints (1.7)

Class/interface/struct/record, enum, delegate and namespaces use source identities; project contexts represent modules. Resolved inheritance and implementation remain distinct (interface extension is inheritance). Type declaration and endpoint evidence carry ranges; supported columns are 1-based, end-exclusive.

Controller profile supports literal/constant class Route, method Route combined with template-less HTTP attributes, HTTP template routes, absolute / or ~/ action routes and controller/action/area tokens. Named attribute properties are not route arguments. NonAction, private/static/generic actions are excluded. Mixed method Route + nonempty HTTP templates, unknown tokens, nonconstant routes, AcceptVerbs and conventional routing produce diagnostics instead of invented routes. Inherited conventions and custom route transformers are outside this profile.

Minimal profile supports literal MapGet/Post/Put/Delete/Patch/Head/Options, bounded nested MapGroup and MapMethods with literal array/collection verbs. Group reassignment, hidden fluent chains, dynamic paths/method lists and fallback/conventional patterns are unsupported diagnostics. A semantically known custom MapGet method is not an ASP.NET endpoint. Findings remain candidates until canonical/runtime confirmation. Coverage reports skipped source count and supported profile names; source snapshot and adapter version are bound by the result envelope.

## N04 — outgoing HTTP (1.8)

Only semantically resolved System.Net.Http.HttpClient calls emit OutgoingHttp. Unknown/fake GetAsync-like receivers never emit HTTP relationships. Absolute literals, const strings, IConfiguration HTTP-key indexers and inline HttpRequestMessage with known HttpMethod are supported. Relative calls can bind named factory registrations or a typed client's single constructor-injected readonly HttpClient field. Local aliases/HttpClient object-initializer BaseAddress are bounded to 12 steps. Mapping evidence includes registration and config references; destination values always expose host/effective port only.

Client names are lookup keys, never service IDs. Duplicate/dynamic/conditional registrations, missing config, multiple constructors and receiver/BaseAddress reassignment stay unresolved/ambiguous. No branch execution, options binding, custom factories or arbitrary method-name resolver is performed. IConfiguration key mapping uses exactly the same project-scoped config references from N02; Java still maps the resulting endpoint alias into canonical service IDs.

Refit adapter publishes explicitly attributed interface endpoint descriptors only; method attribute namespaces are checked when symbols resolve. It does not claim generated Refit calls or automatic AddRefitClient runtime mapping. RestSharp is disabled with a diagnostic. These adapters do not turn interface method names into confirmed HTTP calls.
